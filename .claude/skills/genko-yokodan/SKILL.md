# 原稿横断タスクの進め方

## 前提となる規模

| | |
|---|---|
| 原稿 | `1.md` 〜 `10.md`（巻数＝ファイル名） |
| 話数 | 410話（`## 第N話　タイトル` が1話、`# 章名` が章） |
| 分量 | 73,086行 / 1,562,576文字 ≒ **156万トークン** |
| 1話あたり | 平均 178行 / 3,800字 ≒ 4千トークン |

全文を素で読むと入力156万トークン。**これを毎回やってはいけない。**

補足: `person.md` や Scrapbox の設定資料は本文と一貫していない（README参照）。
CLAUDE.md の通り**情報は常に本文から拾う**。設定資料は仮説の種にはしてよいが、根拠にはしない。

## 大原則

1. **機械にできることをLLMにやらせない。**
   出現数え上げ・候補列挙・箇所特定は `scripts/` のスクリプトでやる（0トークン）。
   LLMは「これは人名か」「この話者は誰か」といった**判断**にだけ使う。
2. **本文を親コンテキストに入れない。**
   本文を読むのはサブエージェント。親が受け取るのは構造化された結果だけ。
   親のコンテキストが本文で埋まると、以降の全ターンにその分の課金が乗り続ける。
3. **中間成果物は必ずディスクに書く。**
   `_yokodan/` 配下に吐く。途中で落ちても再開でき、二度と同じ本文を読まずに済む。
4. **取りこぼしを自覚する。**
   サンプリングした時は「全ヒット何件中、何件を見たか」を必ず出力し、結論にも書く。
   スクリプトはこの数字を出すように作ってある。

## 戦略の選び方

タスクを見て、この順に検討する。**上から順に、成立するなら下には行かない。**

| | 戦略 | 成立条件 | コスト目安 |
|---|---|---|---|
| A | 絞り込み型 | 調べたい対象が語として grep できる（人名・地名・固有名詞・記号・「」） | 全文の 1〜5% |
| B | カバレッジ型 | 対象がN個あり、各対象について数話読めば判断できる | 全文の 3〜15% |
| C | 全走査型 | 全話を1話ずつ判定しないと原理的に答えが出ない | 全文の 100% |
| D | 恒久インデックス | 同種の横断タスクを今後も繰り返す | 初回100%、以降ほぼ0 |

**Cを選ぶ前に必ず立ち止まる。** ほとんどのタスクはA or Bで足りる。
Cが本当に必要なのは「全話の雰囲気を分類」「伏線を網羅列挙」のように、
**事前に検索語を決められない**タスクだけ。Cを実行する前にユーザーに見積りを出して承認を取る。

---

## 戦略A: 絞り込み型

### 手順

1. **母集団を機械的に作る**（0トークン）

   ```bash
   python .claude/skills/genko-yokodan/scripts/vocab.py kata --min 15 --vols 2 --stop
   ```

   カタカナ語なら人名・地名・種族名がほぼ全部拾える（再現率優先、ノイズ込みで約290語）。
   ノイズが混ざるのは織り込み済み。**絞るのは次の工程。**

2. **候補リストだけを読んで判断する**（数千トークン）

   290行のTSVを読み、「これは人名」「これは一般名詞」を仕分ける。
   `vols`（出現巻数）と `total`（出現回数）が判断材料になる。
   例: 「名前がついており複数の話に登場する」＝ `vols >= 2` かつ人名判定が真。

3. **該当箇所だけを文脈つきで抜く**

   ```bash
   python .claude/skills/genko-yokodan/scripts/ctx.py ユズ --count          # 分布を見る
   python .claude/skills/genko-yokodan/scripts/ctx.py ユズ -B2 -A2 --max 30 # 30箇所サンプル
   ```

   `--count` でどの話に何回出るかが分かる。密度の高い話が「その対象が主役の話」。

4. **判断してまとめる。** 根拠は必ず `8.md:1234` 形式の出典つきで残す。

### 迷ったときの検索語の作り方

- 人名・固有名詞 → `vocab.py kata`
- 造語・スキル名・ルビつき語 → `vocab.py ruby`（この作品はルビに固有名詞が集中している）
- 一人称・二人称・口癖 → `vocab.py word 俺 私 僕 ...` で閉じた集合を数え上げ
- セリフの言い回し → `ctx.py "^「" --regex --near <人名>`

## 戦略B: カバレッジ型

対象がN個（キャラ全員、地名全部…）あり、各対象について「その対象が濃く出ている話を数話読めば答えが出る」場合。

```bash
python .claude/skills/genko-yokodan/scripts/cover.py ルナ ユズ アウラ ... --per 2
# または
python .claude/skills/genko-yokodan/scripts/cover.py --file _yokodan/targets.txt --per 2
```

貪欲法で「全対象を `--per` 回ずつカバーする最小の話集合」を選ぶ。
実測: **13キャラを11話（全文の3.1%）でカバー**できた。全走査比 約1/32。

出力の各行に `file / start / end` が入っているので、
サブエージェントに `Read(file, offset=start, limit=end-start+1)` させればよい。

末尾の「カバー状況」で `不足` が出た対象は、出現が薄すぎる。
その対象だけ戦略Aに切り替えて個別に `ctx.py` で拾う。

## 戦略C: 全走査型

本当に全話を判定する必要がある場合のみ。

### 手順

1. **バッチに割る**

   ```bash
   python .claude/skills/genko-yokodan/scripts/manifest.py --batch 1800
   ```

   話境界を壊さない連続行レンジが46バッチ出る（1バッチ ≒ 1,700行 / 3.4万字 / 3.4万トークン）。

2. **見積りをユーザーに提示して承認を取る。** 「46サブエージェント / 入力約156万トークン」。

3. **サブエージェントに投げる**

   - `Agent(subagent_type: "general-purpose", model: "haiku")` を使う。
     抽出は機械的な作業なので Haiku で十分。**統合（reduce）だけメインモデルでやる。**
   - 1エージェント = 1バッチ。並列で投げる。
   - 各エージェントへの指示に必ず含めるもの:
     - `Read("<file>", offset=<start>, limit=<lines>)` で読むこと（ファイル全体を読ませない）
     - 出力スキーマ（JSONL。1行1レコード、フィールド名を明示）
     - **結果を `_yokodan/<タスク名>/batch-<N>.jsonl` に自分で Write すること**
     - 返り値は「書いたパスと件数」だけにすること（本文を親に返させない）
   - 出典として `<file>:<line>` を各レコードに持たせる。

4. **再開可能にする。** 投げる前に `_yokodan/<タスク名>/` を見て、
   既に存在するバッチはスキップする。落ちても続きから再開できる。

5. **reduce する。** 46個のJSONL（合計せいぜい数千行）を親が読んで統合する。
   ここは本文ではないので親コンテキストに入れてよい。

## 戦略D: 恒久インデックス

同種の横断タスクを繰り返すなら、初回だけ戦略Cで**タスク非依存の一次索引**を作る。

`_yokodan/index/hanashi.jsonl` に1話1レコードで:

```json
{"id":123,"file":"3.md","start":4501,"end":4680,"title":"第123話　○○",
 "chars":["ルナ","ユズ"],"place":"王都","summary":"...","events":["..."],"time":"..."}
```

以降のタスクは、まずこの索引（410行 ≒ 4万トークン）を読んで対象話を特定し、
そこから戦略A/Bに落とす。**2回目以降のコストが桁で下がる。**

作る価値があるかはユーザーに聞く。作るなら `_yokodan/index/` はコミット対象にしてよい。

## スクリプト一覧

すべて `.claude/skills/genko-yokodan/scripts/` 配下。リポジトリルートから実行する。
`--help` に使用例あり。出力はUTF-8固定（Windowsのコンソール文字化け対策済み）。

| スクリプト | 用途 |
|---|---|
| `manifest.py` | 話の棚卸し。`--summary` 規模 / `--batch N` 走査バッチ割り |
| `vocab.py` | 候補語の機械抽出。`kata` / `kanji` / `ruby` / `word` / `serifu` |
| `ctx.py` | 該当箇所の文脈つき抽出。`--count` 分布 / `--near` 共起 / `--regex` |
| `cover.py` | 複数対象を最小話数でカバーする話の選定（貪欲法） |

共通の注意:
- `ctx.py` / `vocab.py` / `cover.py` は既定でルビ `《》` と `｜` を除去してから照合する
  （`｜追加データ《パッチ》` のような記法があるため）。`ctx.py --keep-ruby` で無効化。
- `ctx.py --max` のサンプリングは既定で **全巻に均等に散らす**(`--spread`)。
  `--head` にすると先頭から。1巻だけ見て結論を出す事故を防ぐため既定は spread。

## 実例: 「名前つきで複数の話に登場するキャラ全員の一人称」

戦略A＋Bの組み合わせ。全文の約4%で完了する。

```bash
# 1. 人名候補を機械抽出（0トークン、約290語）
python .claude/skills/genko-yokodan/scripts/vocab.py kata --min 15 --vols 2 --stop \
  > _yokodan/ninshou/kata.tsv

# 2. 一人称の語彙が閉じていることを確認（0トークン）
python .claude/skills/genko-yokodan/scripts/vocab.py word 俺 私 僕 ぼく オレ わたし あたし わし ワシ ワタシ 拙者 我輩 儂 おいら
```

3. `kata.tsv` を読んで人名だけに仕分ける → `_yokodan/ninshou/targets.txt`
   （地名・種族名・スキル名を落とす。ここがLLMの仕事）

```bash
# 4. 全人名を2話ずつカバーする話を選ぶ
python .claude/skills/genko-yokodan/scripts/cover.py --file _yokodan/ninshou/targets.txt --per 2
```

5. 選ばれた話をサブエージェント（Haiku）に分担させ、
   「キャラ名 / 一人称 / 出典 file:line / 該当セリフ」のJSONLを書かせる
6. カバー不足のキャラだけ個別に:

```bash
python .claude/skills/genko-yokodan/scripts/ctx.py "^「.*(俺|私|僕|わたし|あたし|ワシ)" \
  --regex --near <キャラ名> --nw 4 -B2 -A2 --max 25
```

7. **検算**: 一人称が判明したキャラについて `ctx.py word` の巻別出現数と突き合わせ、
   途中で一人称が変わっているキャラ（成長・正体判明・憑依など）がないか確認する。
   この作品は正体が明かされる展開があるので、**1キャラ1一人称と決めつけない。**

## やってはいけないこと

- ❌ `Read("5.md")` のようにファイル全体を読む。1ファイルで13万字ある。
  必ず `offset` / `limit` で話単位に絞る。
- ❌ 全文を `Grep` の `output_mode: "content"` で `head_limit` なしに出す。
- ❌ サブエージェントに本文をそのまま返させる。返すのは構造化結果とパスだけ。
- ❌ 1巻だけ読んで「全巻でこうです」と結論づける。10巻は連載期間5年で作風も変わる。
- ❌ `person.md` や設定資料を根拠にする。本文がマスター。
- ❌ 中間結果をディスクに書かずに進める。落ちたら全部やり直しになる。
